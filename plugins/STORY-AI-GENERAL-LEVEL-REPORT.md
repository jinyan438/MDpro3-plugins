# 故事通用 AI：通用星数规划（2026-09-28）

本轮将此前的银河光子龙专用改星判断替换为通用方案。银河光子龙和轮胎同调士的升降星不再使用各自的决策分支；所有已识别效果共用同一套发动、目标组合、数值选择及后续展开搜索。仅修改 `plugins`，没有同步本体或运行正常游戏启动脚本。

## 实现

1. `tools/build_story_level_effects.py` 只读本机 `script.zip` 和卡片数据库，按 Lua 结构提取效果事实：发动区域、目标范围／属性／种族／字段、固定或相对星数、可选数字、目标数量、代价和次数。提取规则没有按卡号判断的分支；生成表中的卡号仅用于匹配核心提供的真实效果。
2. `StoryAiLevelPlanning.cs` 投影改变后的素材星数，使用既有同调、超量、融合、连接和资源展开搜索评估后续。可选效果比较不发动的路线；主阶段主动效果进入统一首步候选比较，防止两张等价来源互相推让而全部不发动。
3. 目标与数字／选项绑定对应来源和效果；结算时按当前场面及核心实际候选重算。除外自身作为代价后仍能找到其待结算计划，多条连锁的数字选择互不覆盖，不往全局数字队列预塞答案。
4. 记录卡名次数、单卡实例次数，离场／新回合正确处理实际实例的重置；每条连锁一次不会错误地变成每回合一次。无法安全预测的条件效果只在核心实际提供合法发动时处理。
5. 搜索不修改真实卡片等级或实际资源。可选改星的“不发动”与全部变星候选各共享一份后续搜索预算，避免目标和数字的组合成倍增加运算。

当前从已安装脚本提取 **35 张卡的 35 个效果**：13 个选择目标、11 个全体己方、10 个自身、1 个召唤事件目标；其中 17 个允许在后续展开中预测。覆盖固定改星、常量升降星、分段强制星数、数字范围、升／降选项、单目标、恰好两个及最多两个目标。银河、科技属、超重武者、六花、光波和全体降星魔法使用相同算法。

这不是完整 Lua 解释器。附带抽卡、特召、未知成本、未知目标谓词或未建模分支的复合效果不提取为免费改星。没有识别的卡继续使用既有通用策略。原先轮胎同调士的追加通召／非调整素材规则属于其他效果，继续保留。

## 验证

基线为此前已完成并通过 4093 项检查的专项修复版本，冻结在 `.selfcheck/story/general-level-start`。旧报告保留为历史记录。本轮结果见同目录的 `STORY-AI-GENERAL-LEVEL-REPORT.json`，包括基线、程序集、脚本、数据库、测试输入和核心的哈希，以及每个场景的关键轨迹。

| 验证 | 结果 |
| --- | --- |
| 本地真实 WindBot／织入入口检查 | **4329 项通过**，比专项基线新增 236 项 |
| 脚本提取器 | **7 组通过**；包括改卡号、改星数、拒绝复合效果／未知代价／未知条件及可重复生成 |
| 独立算术验证 | **60 个匿名卡号局面**，独立计算改变后的同调星数总和 |
| 编译及 IL 后处理 | 通过，包含入口接入、幂等、符号及接口不匹配拒绝 |
| 原生核心真实起手 | **176 对**：快斗 10 级 128 对；同调、超量、融合、连接主轴的其他四副 10 级卡组各 12 对 |
| 原生核心构造局面 | **51 对**：14 种通用改星情况各 3 对，另保留原来的 9 对银河专项回归 |
| 原生核心总执行 | **454 次**；均完整结束，无核心拒绝响应、Lua 错误或测试超时 |

通用构造局面均达成独立指定的目标终场，覆盖自身升星、通召后升星、机械族目标、墓地除外降星、两个目标、可少选目标、全体改星、保留现有星数、科技属升／降选项和轮胎同调士数字选择。相对于专项版本，新增明确修复：

- “能力调整”会把原本能做 8 星同调的素材降成总计 6 星，而额外只有星尘龙时，现在选择不发动并做出星尘龙；旧版三次均错误降星并停住。
- 科技属螺旋桨蛇需要选择降 1 星才能接出星尘充能战士时，现在三次均选对并完成同调；旧版三次均选升星而停住。
- 原有银河回归继续通过：两只 5 星银河战士保留星数；确实需要 4 或 8 星的构造局面选择正确，银河天翔的召唤限制继续生效。

真实起手有 **14 对终场怪兽组合发生变化**（快斗 13 对，同调主轴 1 对），其余 162 对相同。快斗起手中出现 No.38 的场次由 9 增至 15；同调第 4 个样本能继续做出流天救世星龙。完整差异均写入 JSON，**不把所有不同终场自动认定为变强**：部分路线会交换素材、场上数量、手牌与额外资源。融合、其他超量、连接的本次终场组合保持相同。

压力用例同时提供 5 只素材、6 种升降幅度和 8 个额外目标，本机记录为 1013 个后续搜索节点、约 237 ms。真实起手整段首回合运行中位数为 57.5 ms、最大约 4.8 秒；这是测试中的整段回合耗时，不是单次响应延迟或任意卡组的最坏上界。

## 边界与复验

搜索仍是有限预算的启发式规划，不证明任意卡组的最大场或完整比赛胜率；复杂主题限制、效果抗性、被干扰后的连锁和星数关联的其他被动能力仍受既有模型覆盖范围限制。当前只前瞻已核实效果，不凭未知效果虚构资源；每个实际步骤继续由原生核心判定合法性并重新规划。实际离场会重置软次数，纯预测路线对离场后再登场的重复软次数仍保守处理。

```powershell
python -X utf8 plugins/tools/build_story_level_effects.py
python -X utf8 plugins/tools/tests/test_story_level_effects.py
./plugins/tools/story-local-ai-test.ps1
python -X utf8 plugins/tools/tests/story_general_level_cases.py
./plugins/tools/story-core-ai-test.ps1 -SkipCompile -Label general-level-after -Cases plugins/.selfcheck/story/general-level-fixtures.tsv
./plugins/tools/story-core-ai-test.ps1 -SkipCompile -Label general-openings-after -Cases plugins/.selfcheck/story/general-level-openings.tsv
python -X utf8 plugins/tools/tests/story_general_level_report.py
```

报告审计依赖本轮保留的两组 before 基线输出；要重建基线，应使用冻结的专项程序集和同一版本测试传输工具，不能拿当前程序集替代。脚本库更新后应重跑提取器和测试。

改动尚未部署到正常游戏目录。按项目原有插件同步／重建流程后生效；直接运行未重建的旧 EXE 仍是旧逻辑。
